# HTML hidden-text probe: a `noscript` marker that came from scripting off

Date: 2026-11-25. Base: `main` at `d9a0017`. Engine: YARA-X 1.24.0 (not exercised; nothing
here scans with rules), Python 3.12.3, Node 22.23.5, Playwright 1.63.0, Chromium
158.0.8127.36, x86_64 Linux container. Every document was generated by the probe and is
inert; the oracle aborts every request. Every run below is a direct run on this container;
nothing here is hosted CI.

## The report

`docs/research/probe_html_hidden_browser.py` was reported to give one unsound marker in the
`directed` set and in `generate --count 3000 --seed 7`, both under Chromium 158. The
directed case is "noscript inside hidden div":

```html
<!doctype html><html><head><title>t</title></head><body><div style="display:none"><noscript></div></noscript>MARK1 lorem ipsum</div>MARK2 lorem ipsum
```

The browser was recorded drawing `MARK1` (`shown:16`), while
`yara_gate.htmlhidden.html_hidden_texts` called it hidden. The same marker is in the
inline style `all` record of the open pull request cgfixit/yara-gate#362, which leaves it
alone.

## What it was

The reader is right. The render ran with scripting off. **Verified** on the base:

| Oracle run | `directed` unsound | seed 7 unsound | `MARK1` of the case |
| --- | --- | --- | --- |
| `ORACLE_JS=1` (scripting on) | 0 | 0 | `display` |
| `ORACLE_JS` unset (scripting off) | 1, this case | 1, `d734`, the same shape | `shown:16` |

Two parsers, chosen by the scripting flag (HTML standard, "parsing main inbody", the
`noscript` start tag; **sourced, located**: the rule is known and the run below behaves as it
says, but the page was not fetched in this session):

- Scripting on: a `noscript` body is raw text. The `</div>` in it is text, `</noscript>`
  ends it, the `display:none` div is still open, and `MARK1` is in it. Hidden.
- Scripting off: `noscript` is an ordinary element. The `</div>` closes it and the div,
  the stray `</noscript>` is dropped, and `MARK1` is drawn.

`htmlhidden.py` assumes scripting is on, as a person's browser has it, and says so in its
module docstring. The oracle leaves scripting off unless `ORACLE_JS=1`, so that `real`
documents built from files on the machine run no script. Comparing a scripting-off render
against a scripting-on reader gives this marker every time. The
[first HTML reader record](2026-11-10-hidden-html-text.md) made the same mistake at first.
This makes three times.

## The change

No change to the reader. The probe now records how each run was made:

- `html_hidden_oracle.js` writes `__oracle: {chromium, scripting}` into its result.
- `compare` prints that line. With scripting off, it leaves out every document that holds
  `<noscript` and prints how many, as `real` already does when it writes its documents.
  A result from an older oracle has no `__oracle` entry, so `compare` warns that the
  scripting state is unknown and keeps every document.

## Runs

`directed` (447 documents) and `generate --count 3000 --seed 7`, each rendered twice with
the changed oracle, then `compare`:

| Set | Scripting | Left out | Unsound | Hidden to both | Shown to both | Reader shows, browser hides |
| --- | --- | --- | --- | --- | --- | --- |
| directed | on | 0 | 0 | 302 | 546 | 127 |
| directed | off | 5 | 0 | 301 | 541 | 126 |
| seed 7 | on | 0 | 0 | 11,577 | 10,960 | 10,146 |
| seed 7 | off | 282 | 0 | 10,466 | 9,806 | 9,135 |

The drawn file from before the change, for `directed` with scripting off, still reports the
marker and prints `the drawn file does not say whether scripting was on`. `compare` exits 1
on it, as before.

The reader did not change, so no marker the reader shows can have become hidden. Two
renders of the same documents with scripting on differed by one marker between
`shown` and `clipped` (directed: shown to both 547 and 546, reader shows and browser hides
126 and 127). That is layout jitter in the oracle across runs, not a change in the reader.

Checks: `ruff check`, `ruff format --check`, and `mypy --strict` on the probe passed.

## What this does not establish

- Nothing about Firefox or Safari, or a Chromium other than 158.0.8127.36.
- Under scripting off, the documents left out are not compared at all. The scripting-on
  run covers them, and that is the run that matches the reader's assumption.
- No production false-positive rate, and no change to any rule or verdict.
