# PyYAML 6.0.3 to 6.0.4 (2026-11-23)

Source: `main` at `bdd0fa4`, branch `claude/deps-pyyaml-6-0-4`. Linux x86_64, Python 3.12,
YARA-X 1.23.0, 89 compiled local rules. The only change is `uv lock --upgrade-package pyyaml`,
written with uv 0.13.9 (the version that wrote the lock, `revision = 5`); `pyproject.toml` keeps
`pyyaml>=6.0.3`. PyYAML is a scan-path parser and is in `_DETECTOR_PACKAGES`
(`src/yara_gate/scanner.py`), so `detector_sha256` changes and every consumer's cached admission
is stale after this bump.

6.0.4 was uploaded to PyPI on 2026-11-20, inside the seven-day Dependabot wait. The maintainer
chose to bump every tier now. `uv audit` did not run (below), so no advisory was the reason.

## What changed upstream

**Sourced, read.** The two sdists were downloaded from PyPI and compared file by file. The
`CHANGES` entry for 6.0.4 names two pull requests, and the Python source differs in two files:

| Upstream change | Where | Reaches the gate? |
| --- | --- | --- |
| yaml/pyyaml#937, merge key performance | `lib/yaml/constructor.py`, `flatten_mapping` | No. The gate never constructs objects |
| yaml/pyyaml#1010, libyaml recursion control | `yaml/_yaml.pyx`: new `_get_max_nest_level` and `_set_max_nest_level` | No. Nothing calls them, and they are a no-op on libyaml before 0.2.6 |

The rest of the diff is packaging: `Requires-Python` moved from 3.8 to 3.10, a Python 3.15
classifier, and an AlmaLinux line in the libyaml build script. The lock carries cp312 wheels for
macOS (x86_64, arm64), manylinux and musllinux, and Windows (win32, amd64, arm64).

**Verified.** The gate's only YAML reader is `_yaml_escaped_scalars` in `content.py`. It walks
`yaml.parse` events with `CBaseLoader`, which preserves scalar style and never builds a node
graph, resolves an alias, or constructs a value, so `flatten_mapping` is never called. The
installed 6.0.4 reports `__with_libyaml__ = True`, the same C loader as before.
