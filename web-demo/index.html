A gate before the context window

Hold what would steer your agent. Pass what wouldn't.

Real, recorded scanner results for attacks hidden where a quick pattern match cannot see them: an Excel review comment split into runs, SVG text split across CDATA and spans, and a message disguised with small capitals. Other examples cover PDF glyphs, model checkpoints, and nested or concatenated archives. Every attack sits beside a benign near-twin with the same channel and shape, so you can see what is held and what still passes.

This website does not scan anything. It replays saved results. There is no paste box, file upload, or connection to a local scanner. Use the local app for your own content.

    What stayed clean in the measurements
    
      
    Every attack above has a benign twin that the same build recorded as clean, with no findings, under all three policies. Beyond these examples, the bundled rules are measured against benign files on every change:
    
      
    
        
    324 generated benign files
    81 of the 85 bundled rules match none of them. The other four are documented Windows shortcut collisions, one file each (0.31%). CI fails the build if any rule crosses its limit.
    
        
    500 installed documentation and asset files
    The original Phase 1c-small candidate changed no verdicts, incomplete reasons, or finding IDs in this macOS sample. See the reader verification record for scope.
    
        
    Files already on a Linux host
    6,099 HTML, SVG, and XLSX files kept their verdicts when the HTML block, spreadsheet cell, and SVG handler checks arrived; the new SVG rule matched none. Across 3,142 system files, only archives in newly handled formats changed verdict: some are now held as incomplete or advisory, and one jar became clean.
    
        
    Real third-party files
    132 PDFs from the pikepdf and pypdf test suites gained no findings from the PDF text view. 65 joblib test pickles gave the same results as before the deeper pickle walk.
    
        
    Published configuration
    Across 112 devcontainer.json files from published npm and PyPI packages, the dev container rule reported one: an inline sh -c host script, the shape it exists to flag. The other 61 lifecycle commands did not match it.
    
      
    
      
    These are generated, test-suite, published-package, and host files, not your upload traffic, so they are not a production false-positive rate. The rules also carry recorded near-miss pairs that CI requires to stay clean. See measured precision and the verification records.
    
    
    
    
    
      
    Run the real scanner on your own machine
    
      
    With Git, Python 3.12, and uv installed:
    
      
    git clone https://github.com/cgfixit/yara-gate.git
cd yara-gate
uv sync --frozen
uv run yara-gate demo --rules rules
    
      
    Cloning and dependency installation use the network. After installation, the loopback app scans locally with bundled rules, including the twins shown here, and accepts short pastes; this public page cannot. Vendor installation is a separate, explicit step.
    
      
    
        
    Messages & tool results
    Use agent-ingest before an SMS, chat message, or tool response reaches the model. Require a complete clean result.
    
        
    Synced documents
    Use agent-document for corpus files that may quote attacks. Accept only complete clean or the exact notes-only record.
    
        
    Keep the boundary
    Read the same bytes that were scanned. Keep content fenced as data and keep the agent's approval controls. Neither demo installs a consumer integration.

    Privacy and limits, plainly
    
      
    The demo has no analytics, cookies, browser storage, or content submission. Its scripts make no API calls and cannot connect to localhost. Only the static page and its assets load; documentation links navigate when you choose them.
    
      
    GitHub hosts this public site and logs visitors' IP addresses for security. This is not an anonymous or offline service. See GitHub Pages data collection.
    
      
    Recorded results cover only these examples and their pinned source revision. A real clean scan is not proof that content is trustworthy: matching finds patterns someone has written down, with no semantic understanding, OCR, or general decryption, and unsupported or unfinished scans must be held.
