    Low noise needs evidence, not a promise
    
      
    In this curated synthetic set, every attack has a benign twin that the same build recorded as clean, with no findings, under all three policies. Most twins are near-misses on purpose: the same file type, layout, and encoding, and often the same opening words. Beyond these examples, the bundled rules are measured against benign files on every change:
    
      
    
        
    328 generated benign files
    81 of the 85 bundled rules match none of them. The other four are documented Windows shortcut collisions, one file each (0.30%). No structural check reports any of them; a merged PDF is read one font per page. CI fails the build if any rule crosses its limit.
    
        
    15,140 files already on a Linux host
    When the SVG scope test and the full-depth tool-list walk arrived, HTML, SVG, Markdown, JSON, XML, and PDF files under /usr, /opt, and home directories kept every verdict and finding. See the scope and budget record.
    
        
    A false positive removed, not excused
    A page with an inline icon and an unrelated script used to be blocked as active SVG. The rule now needs the script inside the svg element; the pair above records both sides, and a page the scanner cannot scope keeps the strict block.
    
        
    Hidden text needs an instruction
    Templates, review notes, and OCR layers hide text all the time. Hidden Word or PDF text is reported only when an instruction rule also matches inside it. See the hidden-text record for the benign sweep.
    
        
    Real third-party files
    132 PDFs from the pikepdf and pypdf test suites gained no findings from the PDF text view. 65 joblib test pickles gave the same results as before the deeper pickle walk.
    
        
    Published configuration
    Across 112 devcontainer.json files from published npm and PyPI packages, the dev container rule reported one: an inline sh -c host script, the shape it exists to flag. The other 61 lifecycle commands did not match it.
    
      
    
      
    These are generated, test-suite, published-package, and host files, not your upload traffic, so they are not a production false-positive rate. The rules also carry recorded near-miss pairs that CI requires to stay clean. See measured precision and the verification records.
    
    
    
    
    
      
    Run the real scanner on your own machine
    
      
    With Git, Python 3.12, and uv installed:
    
      
    git clone https://github.com/cgfixit/yara-gate.git
cd yara-gate
uv sync --frozen
uv run yara-gate demo --rules rules
    
      
    Cloning and dependency installation use the network. After installation, the loopback app scans the same catalog locally with bundled rules, one pair side by side or every pair at once, and accepts short pastes; this public page cannot. Vendor installation is a separate, explicit step.
    
      
    
        
    Messages & tool results
    Use agent-ingest before an SMS, chat message, or tool response reaches the model. Require a complete clean result.
    
        
    Synced documents
    Use agent-document for corpus files that may quote attacks. Accept only complete clean or the exact notes-only record.
    
        
    Keep the boundary
    Read the same bytes that were scanned. Keep content fenced as data and keep the agent's approval controls. Neither demo installs a consumer integration.

    Privacy and limits, plainly
    
      
    The demo has no analytics, cookies, browser storage, or content submission. Its scripts make no API calls and cannot connect to localhost. Only the static page and its assets load; documentation links navigate when you choose them.
    
      
    GitHub hosts this public site and logs visitors' IP addresses for security. This is not an anonymous or offline service. See GitHub Pages data collection.
    
      
    Recorded results cover only these examples and their pinned source revision. A real clean scan is not proof that content is trustworthy: matching finds patterns someone has written down, with no semantic understanding, OCR, or general decryption, and unsupported or unfinished scans must be held.
